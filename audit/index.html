Audit Nizhamiyyah Edu

Audit keamanan, pembayaran, bug, UX, aksesibilitas, performa, dan kualitas kode dari build production yang diunduh dari hosting. Source .tsx tidak ikut di folder ini, jadi semua temuan dibaca dari kode hasil kompilasi di .next/ dan dari pengujian langsung di localhost.

Kerjakan minggu ini

  1. Upgrade Next.js dan React ke rilis yang sudah ditambal (K1). Versi yang dipakai sekarang punya celah eksekusi kode jarak jauh tanpa login.
  2. Ganti semua secret (AUTH_SECRET, MAYAR_API_KEY, password database) dan build ulang supaya kunci enkripsi server action juga baru (K2).
  3. Tambah konfirmasi dan arsip untuk hapus kursus, supaya siswa yang sudah bayar tidak kehilangan akses (P1).
  4. Buka katalog untuk publik dan perbaiki CTA landing yang sekarang mental balik ke beranda (U1, U2).
  5. Tampilkan pesan error dari server action ke pengguna, jangan biarkan jadi halaman error generik (B1).

Yang sudah bagus

  • Webhook Mayar tidak percaya payload mentah. Transaksi dicek ulang ke API Mayar (server-to-server), lalu nominal, mata uang, dan extraData dicocokkan, dan semuanya ditulis dalam satu transaksi database. Prosesnya juga idempoten.
  • Setiap server action mengecek peran dan kepemilikan kursus (createdById). Admin tidak bisa mengubah perannya sendiri.
  • Siswa kursus berbayar tidak bisa membatalkan pendaftaran sendiri. Kursus gratis dan berbayar dipisah dengan jelas.
  • Video YouTube memakai youtube-nocookie.com. Ada lang="id", aria-label di tombol ikon, dan dukungan prefers-reduced-motion.
  • Atribut data-testid sudah konsisten, jadi siap untuk tes end-to-end.

Semua temuan

Keamanan

K1Kritis

Next.js 15.1.3 dan React 19.0.0 kena celah RCE di React Server Components

Bukti
node_modules/next 15.1.3 dan react 19.0.0. App ini memakai App Router dan Server Actions, jadi termasuk yang terdampak advisori Desember 2025 (CVE-2025-55182 / CVE-2025-66478, "React2Shell"). Rilis 15.1.x berikutnya juga menambal celah DoS dan kebocoran source di protokol yang sama.
Dampak
Request yang dirancang khusus bisa menjalankan kode di server tanpa login. Dari situ penyerang bisa membaca DATABASE_URL, MAYAR_API_KEY, dan AUTH_SECRET.
Perbaikan
Upgrade ke patch terbaru di jalur 15.x (minimal versi yang disebut di advisori Next.js untuk 15.1, atau langsung ke 15.5.x terbaru) dan React 19 yang sudah ditambal. Setelah itu ganti semua secret dan periksa log server sejak Desember 2025, karena server mungkin sudah sempat terekspos. 
npm i next@15 react@19 react-dom@19   # lalu cek versi patch di advisori resmi
npx fix-react2shell-next              # alat cek dari Vercel, kalau tersedia
K2Tinggi

Kunci enkripsi build ikut terbawa di folder yang diunduh

Bukti
.next/server/server-reference-manifest.json berisi encryptionKey. .next/prerender-manifest.json berisi previewModeSigningKey dan previewModeEncryptionKey.
Dampak
Siapa pun yang memegang salinan folder ini bisa membuka atau memalsukan data closure server action selama build yang sama masih jalan di production.
Perbaikan
Build ulang (kunci baru dibuat otomatis), atau tetapkan NEXT_SERVER_ACTIONS_ENCRYPTION_KEY lewat env di hosting. Jangan bagikan folder .next. Kalau butuh bantuan, bagikan repo source-nya saja.
K3Tinggi

Tidak ada security header sama sekali

Bukti
Response GET / hanya membawa X-Powered-By: Next.js. Tidak ada CSP, HSTS, X-Frame-Options/frame-ancestors, Referrer-Policy, X-Content-Type-Options, maupun Permissions-Policy.
Dampak
Halaman dashboard bisa dibingkai di situs lain (clickjacking) untuk menjebak klik di tombol seperti "Simpan" peran atau "Hapus". Versi framework juga terlihat oleh pemindai otomatis.
Perbaikan
// next.config.js
poweredByHeader: false,
async headers() {
  return [{ source: "/(.*)", headers: [
    { key: "Strict-Transport-Security", value: "max-age=63072000; includeSubDomains; preload" },
    { key: "X-Frame-Options", value: "DENY" },
    { key: "X-Content-Type-Options", value: "nosniff" },
    { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
    { key: "Permissions-Policy", value: "camera=(), microphone=(), geolocation=()" },
    { key: "Content-Security-Policy", value: "frame-ancestors 'none'; frame-src https://www.youtube-nocookie.com" },
  ]}];
}
K4Sedang

Webhook Mayar tanpa autentikasi pengirim dan tanpa rate limit

Bukti
src/app/api/webhooks/mayar/route.ts menerima POST dari siapa saja. Setiap payload dengan orderId valid memicu panggilan ke API Mayar. Response juga membocorkan detail, misalnya "Payment amount mismatch" atau "Order is cancelled".
Dampak
Tidak bisa dipakai untuk membuka kursus gratis, karena verifikasi ke Mayar menahannya. Tapi endpoint ini bisa dibanjiri request sampai kuota API Mayar habis dan log penuh, dan status order bisa ditebak dari pesan errornya.
Perbaikan
Verifikasi token webhook dari dashboard Mayar (header atau secret di URL webhook), tolak lebih awal kalau tidak cocok, pasang rate limit per IP, dan balas dengan pesan generik (200 {received:true}). Detailnya cukup ditulis di log.
K5Sedang

Validasi URL video longgar, iframe bisa memuat domain lain

Bukti
Halaman pelajaran memakai hostname.includes("youtube.com"). Untuk path /embed/, URL aslinya dipakai mentah-mentah sebagai src iframe tanpa sandbox. Contoh: https://youtube.com.situs-palsu.id/embed/x lolos.
Dampak
Akun pengajar (atau akun pengajar yang dibobol) bisa menyisipkan halaman phishing seperti "login ulang Google" di dalam pelajaran.
Perbaikan
Cocokkan hostname secara persis (youtube.com, www.youtube.com, m.youtube.com, youtu.be), ambil ID video saja, lalu bangun ulang URL youtube-nocookie.com/embed/{id}. Tambahkan sandbox="allow-scripts allow-same-origin allow-presentation" dan referrerPolicy.
K6Rendah

Input server action tanpa skema dan batas panjang

Bukti
Judul, deskripsi, dan materi pelajaran tidak punya batas panjang. Harga hanya Math.max(0, floor) tanpa batas atas, jadi angka di atas 2.147.483.647 membuat Prisma error (tipe Int).
Perbaikan
Validasi dengan zod di setiap action: judul maksimal 120 karakter, deskripsi 1.000, materi 50.000, dan harga antara 0 sampai 50.000.000.
K7Rendah

Perubahan peran tanpa jejak audit

Bukti
/dashboard/admin: admin bisa menurunkan semua admin lain dengan satu klik "Simpan", tanpa konfirmasi dan tanpa log.
Perbaikan
Tambah tabel AuditLog (siapa, kapan, dari peran apa ke peran apa), minta konfirmasi untuk perubahan ke atau dari ADMIN, dan cegah admin terakhir diturunkan.
K8Rendah

/api/health terbuka untuk publik

Bukti
Endpoint ini mengembalikan status koneksi database (connected/disconnected/not_configured) ke siapa saja.
Perbaikan
Kembalikan {status:"ok"} saja ke publik. Detail database cukup untuk request yang membawa token monitoring.

Pembayaran dan data

P1Tinggi

Hapus kursus sekali klik, tanpa konfirmasi, ikut menghapus akses siswa berbayar

Bukti
Di /dashboard/kelola, tombol "Hapus" langsung menjalankan course.delete. Hapus pelajaran punya konfirmasi, tapi hapus kursus tidak.
Dampak
Satu salah klik menghapus kursus beserta enrollment (lewat cascade) siswa yang sudah membayar. Ini memicu komplain dan refund.
Perbaikan
Ganti jadi arsip (archivedAt), bukan hapus. Tolak penghapusan permanen kalau ada order PAID. Tambahkan dialog konfirmasi yang meminta pengguna mengetik judul kursus.
P2Sedang

Order PENDING menumpuk dan bisa dobel

Bukti
expiredAt tidak dikirim ke Mayar dan tidak ada job yang membatalkan order kedaluwarsa. Setelah 2 jam, klik "Beli" lagi membuat order dan invoice baru. Klik dobel juga bisa membuat dua order sekaligus.
Perbaikan
Kirim expiredAt (misalnya 24 jam), tandai order lama EXPIRED lewat cron, kunci tombol saat request berjalan (useFormStatus), dan pakai unique index parsial untuk satu PENDING per user per kursus.
P3Sedang

Banner status pembayaran tidak mencerminkan status sebenarnya

Bukti
/dashboard/kursus?orderId=APA_SAJA selalu menampilkan "sedang diproses" beserta ID mentah, tanpa mengecek order itu milik siapa dan apa statusnya.
Dampak
Siswa yang pembayarannya gagal tetap diberi tahu "sedang diproses", sementara yang sudah lunas melihat pesan yang membingungkan.
Perbaikan
Ambil order milik user tersebut, lalu tampilkan status nyata: lunas (dengan tombol "Mulai belajar"), menunggu (dengan auto-refresh tiap 5 detik), atau gagal/kedaluwarsa (dengan tombol "Bayar ulang").
P4Sedang

Harga tidak bisa diubah, dan kursus baru langsung tayang walau masih kosong

Bukti
Form "Sunting Kursus" tidak punya field harga. createCourse menyimpan published: true walaupun belum ada pelajaran.
Perbaikan
Tambahkan field harga di form edit (kunci kalau sudah ada pembelian, atau catat riwayat harga). Kursus baru dibuat sebagai draft, dan baru bisa dipublikasikan kalau sudah ada minimal 1 pelajaran.
P5Rendah

Domain produksi tertanam saat build

Bukti
"https://belajarditimurtengah.com" tertulis langsung di bundle untuk redirectUrl Mayar.
Perbaikan
Baca dari env runtime (APP_URL) di server, jangan dari NEXT_PUBLIC_* yang di-inline saat build, supaya staging tidak mengarahkan pembeli ke production.

Bug fungsional

B1Tinggi

Pesan error tidak pernah sampai ke pengguna

Bukti
Semua action memakai throw Error("Nomor WhatsApp tidak valid…"). Di production Next.js menyamarkan pesan ini, dan tidak ada error.tsx di build.
Dampak
Siswa yang salah ketik nomor WA saat checkout langsung melihat layar error generik, padahal ini momen paling mahal di funnel.
Perbaikan
Action mengembalikan { ok:false, error:"…" }, lalu form memakai useActionState untuk menampilkan pesan di bawah field. Tambahkan juga app/dashboard/error.tsx berbahasa Indonesia sebagai jaring pengaman.
B2Sedang

Angka "Kursus Aktif" di Ringkasan mentok di 3

Bukti
/dashboard: query enrollment memakai take: 3, lalu .length-nya dipakai sebagai statistik dan label "Buka Kursus Saya (3)".
Perbaikan
Hitung pakai enrollment.count() yang terpisah dari daftar 3 kursus terakhir.
B3Sedang

Pengajar dan admin melihat tombol "Tandai Selesai" yang selalu gagal

Bukti
Halaman pelajaran mengizinkan pemilik kursus dan admin masuk tanpa enrollment, tapi action markComplete mewajibkan enrollment ACTIVE. Akibatnya klik berujung error.
Perbaikan
Sembunyikan kartu progres untuk mode pratinjau dan tampilkan label "Mode pratinjau pengajar".
B4Rendah

Karakter rusak "â€”" di halaman Profil

Bukti
Fallback untuk nama atau metode login kosong tersimpan sebagai "â€”", yaitu em dash yang ter-encode dua kali (file source disimpan bukan UTF-8).
Perbaikan
Simpan ulang file sebagai UTF-8 dan pakai "—" atau teks "Belum diisi".
B5Rendah

Slug tidak berguna untuk judul Arab dan tidak dipakai di URL

Bukti
Regex [^a-z0-9] mengubah judul seperti "متن الآجرومية" menjadi kursus, kursus-2, dan seterusnya. Semua rute juga memakai id, bukan slug.
Perbaikan
Transliterasi atau minta slug manual, lalu pakai slug di URL publik /kursus/[slug] (lihat U2).
B6Rendah

Materi pelajaran kehilangan format

Bukti
Konten hanya dipecah dengan split("\n\n"). Enter tunggal hilang dan tidak ada tebal, daftar, kutipan, atau teks Arab kanan-ke-kiri.
Perbaikan
Pakai Markdown yang disanitasi (misalnya react-markdown + rehype-sanitize), dan tambahkan blok <p dir="rtl" lang="ar"> dengan font Amiri untuk matan kitab.

UX dan konversi

U1Tinggi

Enam CTA di landing tidak berfungsi untuk pengunjung baru

Bukti
"Jelajahi Katalog Kursus", "Masuk ke Portal", "Pilih Kursus Sekarang", dan tiga tombol lain mengarah ke /dashboard…. Tamu yang belum login dialihkan diam-diam ke /. Sudah dicoba di localhost: klik, lalu kembali ke beranda tanpa pesan apa pun.
Dampak
Pengunjung mengira situsnya rusak. Ini kebocoran konversi terbesar di funnel.
Perbaikan
Katalog dibuat publik di /kursus. Tombol yang memang butuh login memanggil signIn("google", { callbackUrl }), supaya setelah login pengguna kembali ke halaman yang dituju.
U2Tinggi

Tidak ada halaman detail kursus sebelum membeli

Bukti
Katalog hanya menampilkan kartu dengan judul, deskripsi, jumlah pelajaran, dan harga, lalu tombol bayar. Silabus baru terlihat setelah terdaftar.
Perbaikan
Buat /kursus/[slug] publik yang berisi kitab rujukan, pengajar dan sanadnya, daftar pelajaran, durasi total, 1 pelajaran pratinjau gratis, FAQ kursus, dan harga yang jelas. Halaman ini juga jadi bahan utama SEO.
U3Sedang

Tombol masuk tersembunyi di layar kecil

Bukti
Di lebar 375px, "Masuk dengan Google" hanya ada di dalam menu hamburger. Di lebar 800px, navigasi desktop juga sudah berubah jadi hamburger. Hamburger baru bekerja setelah JS selesai hidrasi.
Perbaikan
Tampilkan tombol "Masuk" ringkas di header pada semua ukuran layar. Navigasi desktop baru dilipat di bawah sekitar 720px. Pakai <details> atau link anchor supaya menu tetap bisa dibuka tanpa JS.
U4Sedang

Landing penuh klaim, minim bukti

Bukti
Tinggi halaman 6.568px di ponsel. Ada klaim "silabus mu'tamad", "kitab muktabar", dan "Database Terproteksi", tapi tidak ada nama kitab, nama pengajar, foto, testimoni, atau contoh materi. Bagian katalog di landing kosong.
Perbaikan
Ganti 4 kartu "keunggulan" generik dengan peta jenjang yang konkret (kitab per marhalah), profil pengajar, dan contoh 1 pelajaran. Buang klaim teknis seperti "Database Terproteksi" karena tidak berarti apa-apa bagi siswa.
U5Sedang

Dashboard penuh elemen mati

Bukti
Sidebar memuat 3 menu "Segera Hadir" (Progres, Sertifikat, Pengaturan). Ada 2 kartu display:none di Ringkasan. Halaman Profil menampilkan ID internal pengguna (cuid), dan Ringkasan mengulang info akun yang sama dengan Profil.
Perbaikan
Hapus menu yang belum ada. Jadikan Ringkasan berfokus pada "Lanjutkan belajar": pelajaran terakhir, progres per kursus, dan langkah berikutnya.
U6Sedang

Alat pengajar masih minim

Bukti
Urutan pelajaran tidak bisa diubah, materi hanya textarea polos, tidak ada pratinjau sebelum tayang, dan tidak ada data siswa per kursus.
Perbaikan
Tambahkan drag-to-reorder, editor Markdown dengan pratinjau, status draft per pelajaran, dan tab "Siswa" yang menampilkan progres.
U7Rendah

Halaman 404 dan error bawaan, berbahasa Inggris

Bukti
URL yang tidak ada menampilkan layar hitam "404 This page could not be found."
Perbaikan
Buat app/not-found.tsx dan app/error.tsx bermerek dengan tautan ke katalog.
U8Rendah

SEO dan share minim

Bukti
Tidak ada favicon, OG image, sitemap, robots, atau metadata per halaman. Semua halaman berjudul sama.
Perbaikan
Gunakan app/icon.png, opengraph-image.tsx, sitemap.ts, generateMetadata per kursus, dan JSON-LD Course.
U9Rendah

Katalog tanpa pencarian dan filter

Perbaikan
Tambahkan filter bidang ilmu (Nahwu, Fiqih, Aqidah, dan lain-lain), tingkat, serta gratis/berbayar, plus sampul kursus. Simpan filter di query string supaya bisa dibagikan.

Aksesibilitas

A1Sedang

Kontras warna emas dan teks muted gagal WCAG AA

Bukti
--gold-600 #B8860B di atas putih hanya 3,3:1, padahal dipakai untuk eyebrow, harga, dan angka langkah. --gold-500 #D4AF37 2,1:1. --muted #5C7A6F di atas #F8F7F3 sekitar 4,4:1. Batas minimum teks kecil adalah 4,5:1.
Perbaikan
Untuk teks, pakai emas yang lebih gelap (misalnya #8A5C0A, sekitar 5,4:1). Warna emas terang cukup untuk dekorasi dan latar.
A2Sedang

Fokus keyboard hampir tidak terlihat

Bukti
Hanya ada 1 aturan :focus-visible di seluruh CSS (44 KB).
Perbaikan
Pasang outline global :focus-visible { outline: 2px solid var(--ring); outline-offset: 2px } untuk semua link, tombol, dan input.
A3Rendah

Target sentuh kecil dan landmark salah tempat

Bukti
Tautan footer hanya setinggi 18px. <header> dan <footer> ada di dalam <main>.
Perbaikan
Beri padding supaya target minimal 44px. Susun struktur jadi header, main, footer sebagai saudara.

Performa

F1Sedang

Landing dirender ulang dari database di setiap kunjungan

Bukti
app/page.js memakai dynamic = "force-dynamic", dengan response Cache-Control: no-store. Setiap kunjungan menjalankan lookup sesi dan query kursus.
Perbaikan
Render landing secara statis dengan revalidate = 300. Bagian yang bergantung pada login (nama dan tombol header) dibuat jadi komponen klien kecil.
F2Sedang

Query database berulang dan berurutan

Bukti
Sesi memakai strategi database (1 query). Layout mencari user via email (1 query), lalu halaman mencarinya lagi (1 query). Halaman pelajaran menjalankan sekitar 7 query berurutan.
Perbaikan
Masukkan id dan role ke sesi lewat callback session, bungkus getCurrentUser dengan React.cache(), dan jalankan query yang independen dengan Promise.all.
F3Rendah

Font dimuat lewat @import yang memblokir render

Bukti
CSS diawali @import url(fonts.googleapis.com…) untuk 3 keluarga font (termasuk Amiri di semua halaman). next-font-manifest kosong.
Perbaikan
Pakai next/font/google (self-host, tanpa layout shift), dan muat Amiri hanya di halaman yang menampilkan teks Arab.

Kualitas kode

Q1Sedang

Logika auth dan user diduplikasi di banyak modul

Bukti
Fungsi "ambil user dari sesi via email" muncul setidaknya di 4 tempat (modul guard, actions katalog, actions pelajaran, layout), masing-masing dengan pengecekan yang sedikit berbeda.
Perbaikan
Satu lib/auth-guard.ts yang berisi requireUser(), requireRole(), dan requireCourseOwner(), dipakai oleh semua page dan action.
Q2Rendah

CSS sulit dirawat

Bukti
Ada 9 breakpoint berbeda (360 sampai 1025px), 23 !important, banyak style={{…}} inline di JSX, dan nama token yang menyesatkan (--parchment justru hijau tua, sisa tema gelap lama).
Perbaikan
Seragamkan jadi 3 breakpoint (640/960/1200), pindahkan inline style ke kelas, dan ganti nama token sesuai perannya (--text, --surface, --accent).

Kepatuhan dan bisnis

L1Tinggi

Belum ada Kebijakan Privasi, S&K, Kebijakan Refund, dan kontak

Bukti
Footer hanya berisi navigasi dan klaim keamanan. Situs mengumpulkan email, foto profil Google, dan nomor WhatsApp, lalu meneruskannya ke Mayar.
Dampak
UU PDP No. 27/2022 mewajibkan pemberitahuan pemrosesan data. Payment gateway juga umumnya mensyaratkan halaman refund dan kontak yang jelas.
Perbaikan
Buat halaman /privasi, /syarat, /refund, dan /kontak, tautkan di footer dan di dialog checkout ("Dengan membayar, Anda menyetujui…").

Keterbatasan audit

Audit ini dibuat dari build production tanpa source asli, skema Prisma, atau file .env. Database dan login Google tidak bisa dijalankan di lokal, jadi halaman dashboard dinilai dari kode hasil kompilasinya, bukan diklik langsung. Skema relasi (misalnya cascade delete) disimpulkan dari perilaku kode. Cocokkan nomor versi patch di K1 dengan advisori resmi Next.js dan React sebelum upgrade.
